# 模型包与 2D / 3D 接入

## 已实现的范围

版本 1 模型包是现有程序化猫咪的外观与绘制器声明，文件扩展名为 `.kurocat.json`，编码为 UTF-8。导入后沿用对应绘制器的姿态、道具动作、连续打字、抚摸、打盹与起床气反应。模型包无需附带脚本、贴图或动画文件。

目前没有任意 GLB / GLTF / VRM / Live2D / Spine 骨架加载器，也没有在线付费商店。GitHub 模型库是用户主动加载的 JSON 目录，支持查看名称、作者、许可、模式与动作列表，然后确认导入。这里的“预览”是信息与能力预览；实际外观在导入并使用后显示。

同一外观在 Canvas 2D 和 Three.js 3D 中的表现可能不同，尤其是二维花纹与斑点。声明两种适配器不代表两种外观逐像素一致。大肥鱼使用专用 2D 绘制器，暂不支持此猫咪模型包格式。

## 在 UI 中操作

1. 右键猫咪，打开“模型库”页签。顶部显示当前模型的模式与可用动作。
2. 点击文件选择器，选中 UTF-8 `.kurocat.json`。系统先验证版本、颜色、适配器和大小，再显示作者、许可与动作。
3. 点击“导入并使用”。若相同 ID 已存在，需要明确勾选“替换同 ID 的已有模型”；内置 ID 不允许被模型包覆盖。导入只包含外观与能力声明，不会替换全局键帽、音效或隐私设置。
4. 点击“导出当前模型包”。桌面版将文件保存到应用配置目录的 `exports/`，并显示完整路径；同名文件自动加序号。浏览器预览使用浏览器下载。
5. 也可以在 GitHub 目录输入框填写 Raw 地址，加载后选择一个模型，再执行相同的预览、导入步骤。加载目录本身不会安装或切换模型。

内置猫导出时 ID 自动追加 `-custom`，便于制作自己的版本。自定义模型保留自己的 ID。模型包的元数据和外观保存在 `cats.json`，不需要独立模型数据库。

配置目录：Windows 为 `%APPDATA%\kuro-cat-pet`；macOS 为 `~/Library/Application Support/kuro-cat-pet`；Linux 为 `~/.config/kuro-cat-pet`。

## 完整示例

仓库提供可直接导入的 [薄荷云朵](../model-store/mint-cloud.kurocat.json)。一个最小可用包如下：

```json
{
  "format": "kurocat-model",
  "version": 1,
  "profile": {
    "adapters": [
      "canvas-cat-v1",
      "three-cat-v1"
    ],
    "behaviorContract": "cat-v1",
    "author": "KuroCat 示例",
    "license": "MIT"
  },
  "skin": {
    "id": "my-cat",
    "name": "我的猫咪",
    "furColor": "#c9e9dc",
    "eyeColorTop": "#558b79"
  }
}
```

| 字段 | 规则 |
| --- | --- |
| `format` / `version` | 固定为 `kurocat-model` / `1`；不支持的版本直接拒绝 |
| `profile.behaviorContract` | 固定为 `cat-v1` |
| `profile.adapters` | 非空且不重复；可选 `canvas-cat-v1`、`three-cat-v1` |
| `profile.author` / `license` | 可选文本，各最多 100 个字符 |
| `skin.id` | 1–36 位小写字母、数字、下划线、短横线；首位为字母或数字；不能占用内置 ID |
| `skin.name` / `emoji` | 名称必填、最多 48 字符；图标可选、最多 12 字符 |
| `skin.furColor` / `eyeColorTop` | 必填颜色；支持 `#RRGGBB`、`rgb(...)`、`rgba(...)` |
| `skin.pattern` | 可选 `solid`、`bicolor`、`tuxedo`、`tabby`、`calico`、`siamese` |
| `skin.spots` | 可选，最多 64 个；部位为 `head`、`body`、`leftArm`、`rightArm` |

其他支持的颜色与布尔字段见 [共享契约](../src/modelContract.json) 的 `skinRules`；斑点坐标系可通过 MCP `get_cat_schema` 查询。每个斑点的 `x/y/rotation` 绝对值不超过 360，`rx/ry` 大于 0 且不超过 300，`opacity` 为 0–1。`rotation` 默认 0，`opacity` 默认 1。文本不允许控制字符，颜色和数字均做校验。

单个模型包不超过 256 KiB。只提取支持的外观字段，未知字段不会作为脚本或资源执行。模型包的 `skin.builtin` 不会获得内置模型权限。

## 动作与反应契约

UI、MCP 和 OBS 读取同一个 [modelContract.json](../src/modelContract.json)。新增绘制器时先声明能力，再接入动作调度，避免菜单出现模型无法完成的动作。

| 动作 ID | 行为 | 2D 猫 | 3D 猫 |
| --- | --- | --- | --- |
| `drink` | 完整端杯、饮用、放回；需要启用道具 | 支持 | 支持 |
| `stretch` / `wave` / `tilt` | 伸懒腰、挥手、歪头 | 支持 | 支持 |
| `slowBlink` / `groom` / `cuddle` | 慢眨眼、洗脸、撒娇 | 支持 | 支持 |
| `nap` | 打盹，进入可被输入吵醒的睡眠状态 | 支持 | 支持 |
| `tailGround` | 手动触发拍尾起床气，随机 2–5 秒 | 支持 | 支持 |
| `calm` | 安抚当前起床气，平滑收尾 | 支持 | 支持 |
| `roll` / `listen` / `shimmy` / `pawCheck` | 地上打滚、侧耳听、抖毛、检查爪子 | 不支持 | 支持 |

大肥鱼仅声明 `drink`、`stretch`、`wave`。MCP 保留 `sleep`→`nap` 的旧名兼容；`roll` 在 3D 中是真正打滚，不再映射成撒娇。

| 输入或状态 | 需要呈现的反应 |
| --- | --- |
| 键盘 | 前爪敲击与可配置尾巴敲键，停止输入后不继续假敲键 |
| 连续输入 | 专注 `focus`、律动 `groove`、兴奋 `excited`、烦躁 `grumpy`，配合眼皮、耳朵、身体和可读字幕 |
| 鼠标 | 跟随、按键、滚轮；普通移动不吵醒打盹中的猫 |
| 睡眠被打断 | 非重复键盘按下、鼠标按下或滚轮触发起床气；尾巴蓄力、落地、回弹，出现冲击特效和提示 |
| 起床气结束 | 随机 2–5 秒自动恢复；继续输入不会续时；来回抚摸可提前安抚，并显示爱心与反馈 |
| 道具 | 咖啡提神、奶茶满足、可乐气泡、能量饮兴奋、布丁享受；包含拿取和放回 |
| 隐私 | 清除输入状态、暂停互动反馈，不显示输入内容或触发输入音效 |

反馈优先级为：起床气 > 安抚 > 道具反馈 > 打字反馈。拍尾反应及淡出期间不叠加喝水和其他待机动作。切换模型或停止绘制器会清理反应，普通设置同步不会重新计时。2D / 3D 都遵循相同时间规则，但按各自骨架绘制。

## 发布 GitHub 模型目录

仓库内 [model-store/catalog.json](../model-store/catalog.json) 是可复制的示例目录。目录格式为：

```json
{
  "format": "kurocat-catalog",
  "version": 1,
  "models": []
}
```

上面是合法的空目录；向 `models` 数组中添加完整模型包对象即可发布，不能只放文件名或 URL。含一个模型的完整目录见仓库示例。目录最多 50 个包，总大小不超过 256 KiB，同一目录内 ID 不得重复。内嵌包减少了额外网络请求，也避免目录与单个下载文件不同步。

将文件提交并推送到自己的 GitHub 仓库后，复制它的 Raw 地址：

```text
https://raw.githubusercontent.com/<owner>/<repo>/<branch-or-commit>/model-store/catalog.json
```

推荐用提交 SHA 固定目录版本。读取仅接受 `raw.githubusercontent.com` 的 HTTPS 地址，禁止跳转和身份凭据，超时 10 秒，按流限制大小并严格检查 UTF-8。私有仓库认证、付费购买、自动更新、卸载管理、搜索与分类尚未实现。本地示例在推送前没有可用的线上 Raw 地址。

## MCP 使用

- `get_model_contract`：读取版本、适配器、动作与反应清单。
- `import_model_pack`：参数 `package` 为完整包对象；`replace`、`activate` 默认 `false`。已有 ID 必须显式替换，激活时自动选兼容模式。
- `export_model_pack`：传入 `id`，返回 JSON，由调用端保存为 UTF-8；不会直接写桌面文件。
- `get_idle_actions`：返回当前模型、模式、可用动作和自动待机设置。
- `trigger_idle_action`：按 `kind` 请求动作，例如 `nap`、`tailGround`、`calm`；不修改自动待机开关。请求可能因隐私或冲突中的互动被忽略，返回成功表示请求已保存，并非动画已播完。
- `get_mood`：返回保存的情绪请求与序号，不代表实时渲染状态。起床气安抚用 `calm`，不是把烦躁表清零。

## 后续外部骨架接入方案（尚未实现）

现有 `profile.adapters` 是扩展入口。后续增加新的适配器 ID 和新版包格式，不改变版本 1 包的含义。建议分三步实现：

1. **统一运行时接口。** 从目前两套引擎抽出 `load/dispose`、`resize`、`update`、`handleInput`、`triggerAction`、`setPrivacy`、`getHitRegions`。行为层负责状态转换、计时、优先级；渲染层负责姿态与特效，UI 只读能力表。
2. **资源与骨架映射。** 为 GLB/VRM 增加网格、骨骼、动画片段和材质资源；为 Live2D/Spine 增加参数映射。需要映射头、耳、身体、双臂、爪、尾巴各节和眼皮，明确单位、朝向与地面高度。模型须声明缺失动作及降级策略，不能承诺自动兼容任意骨架。
3. **编辑与分发工具。** 在 UI 增加骨架映射、挂点调整、动作预览、碰撞范围预览、批量反应验收、缩略图与版本迁移。模型库再加入标签、搜索、许可筛选和明确确认后的更新。

| 接入部件 | 外部模型需要提供的信息 | 验收要求 |
| --- | --- | --- |
| 道具挂点（socket） | 左右爪握持点、嘴部接触点、杯子局部握点、桌面落点 | 端起时手杯同步；饮用接近嘴部；放回原位；中断不悬空 |
| 逆向运动学（IK） | 上臂、前臂、爪骨及弯曲方向约束 | 任意缩放与左右道具位置下，爪能接触目标 |
| 动画混合 | 待机、睡眠、起身、抚摸、四种打字反应、各道具、拍尾、打滚片段或参数 | 输入可中断；退出有过渡；不得持续假敲键 |
| 地面与尾巴 | 尾根、尾链、尾尖接触点、身体地面高度 | 尾根不脱离；落地瞬间发特效；身体和尾尖不穿地 |
| 表情与特效 | 眼皮遮挡、眼睛、耳朵、字幕锚点、爱心/冲击挂点 | 文字不裁切；起床气与安抚可区分；遵守隐私与反馈优先级 |
| 点击区域 | 模型轮廓、道具实际边界和可抚摸区域 | 点击杯柄、吸管有效；透明空白可穿透 |
| 生命周期 | 卸载资源、撤销监听、释放材质/纹理/音频、取消异步加载 | 重复切换无旧动作、无持续音频、无资源累积 |

模型包目录只分发数据和资源，行为代码由应用自带适配器提供。新适配器先通过共同动作契约回归，再开放到导入 UI 和 MCP。

## 验证

已有依赖时可运行以下检查，无需打包：

```sh
node node_modules/typescript/bin/tsc --noEmit
node scripts/check-pet-motion.mjs
```

回归脚本需要 Node 22.15+，覆盖状态时序、动作中断、尾尖接地、完整 2D 特效绘制路径、包格式、中文与目录下载校验。它模拟 Canvas/WebGL 绘制，不替代安装包中的视觉与原生窗口测试。Rust 模型校验单元测试和安装包构建交给 GitHub Actions。
