# 3D 奶蛙设计与接入方案

状态：**设计方案，尚未实现 3D 奶蛙加载器**。当前内置奶蛙仍使用 `canvas-naiwa-v1`，仅支持 2D。本文提出后续制作规格，不代表现有导入器已支持这些文件。

## 先定外形，再做动作

推荐采用 **Blender 制作连续皮肤网格、软手臂骨架和表情形态键，再接入 Three.js**。参考是用户提供的多视图设计图，见 [参考图](../src/assets/naiwa/reference.webp)。优先完成参考图的坐姿和趴姿，在实际桌宠显示大小下验收轮廓，再制作动作。

- 头与身体连成一个柔软整体；保留略扁的头顶、饱满腹部、奶油色肚皮和贴近面部的绿色眼睛。侧面深度参考侧视图，避免只把正面图拉厚。
- 身体到肩、手臂、掌心与三指使用连续拓扑和渐变权重。不要用彼此相交的圆柱、球或独立掌片拼出关节；不能留下明显肩缝和手腕接缝。
- 双脚位于身体两侧，坐着时折腿收住，脚掌能小幅交替摆动。没有耳朵、尾巴或猫咪胡须。
- 趴睡是身体伏到键盘后沿：头身压低并摊宽，前臂向内放松，下巴靠近键盘；后腿收在身体后侧。通过姿态和修正形变实现，不能只缩小身体或把整张脸往下平移。
- 材质以柔和、略带光泽的皮肤为目标，肚皮和手脚色区遵循参考图。先用基础材质看准比例，再调光照，避免用强反光掩盖模型缺陷。

建议首版预算：桌面版 12k–20k 三角面、30–45 根变形骨、至多两套 1K 贴图；移动端另做约 6k–10k 三角面的简化版本。预算是待实测的制作目标，不是已验证的性能保证。第一版使用基础材质和未压缩 GLB，减少接入变量。

## 骨架与“液态手臂”

制作骨架分为作者操作的控制骨与导出的变形骨。身体设置根、骨盆、腹部、胸部和面部控制；双腿保留髋、膝、踝及脚趾控制，但用皮肤过渡隐藏硬折角。

每侧手臂建议使用 4–6 段变形骨，覆盖肩到掌的弧线。各段控制伸缩和弯曲，权重连续过渡，掌心朝向与指尖接触位置分别控制。“液态”首先是这种软形变表现，不需要在桌宠运行时做流体模拟。

运行时接触优先：从实际键盘、鼠标或杯子的目标点求出手臂姿态（逆向运动学，IK），保持指尖或掌心贴合，再叠加少量中段回弹。伸长时适度变细，收回时恢复体积；超过允许长度时侧移身体或换手，不能无限拉长。鼠标上的手指只轻压按键上缘，保留按键可见面积。

Blender 中可以使用控制约束辅助制作，但交付应以普通变形骨、形态键以及烘焙后的动画为准；控制器、程序修改器或软体模拟的效果不能直接视为运行时能力。第一份 GLB 必须做导出再载入验证，检查坐标轴、骨骼缩放、法线和形态键是否一致。

## 表情使用局部形态键

形态键（Morph Target）保存网格的另一种形状，通过权重平滑混合。建议的名称如下，最终由新适配器验证与映射：

| 通道 | 设计要求 |
| --- | --- |
| `lidCloseLeft/Right` | 上眼皮真正覆盖眼球，闭眼时只有柔和弧线；不得露出第二道绿色眼球边缘 |
| `lidAngryLeft/Right` | 内侧压低，表达不满；可与眨眼混合，不用两根眉线代替眼皮 |
| `cheekPuffLeft/Right` | 只在嘴巴两侧鼓起，保持眼睛与头部外轮廓；生气时可略不对称 |
| `mouthOpen / mouthPout / mouthSmile` | 饮用、抿嘴和满足表情；口部接触点随变形更新 |
| `bodySquash / bellyBreathe` | 蓄力、落地、呼吸的体积变化，避免单纯全局缩放造成脚底滑动 |
| `proneCorrective / shoulderRelaxLeft/Right` | 修正坐姿到趴姿的腹部、肩部轮廓，防止肩缝和手臂穿身 |
| `gripLeft/Right / fingerPressLeft/Right` | 握杯和按键的掌指收拢，不改变手臂接触目标 |

两只眼球可独立转向；肚皮不另贴一个悬浮椭球，使用连续表面上的材质色区。嘴边鼓腮的网格密度应足够，但不要改变整张脸的比例。

## 动作与输入的配合

身体的主要表演可以在 Blender 制作成片段，键鼠、杯子、嘴部对位留给运行时接触求解。不要把手与道具都绑定在一个只适合固定桌面布局的动作里。

| 动作组 | 动作设计与接入 |
| --- | --- |
| 普通待机 | 呼吸、自然眨眼、短暂看向鼠标；运动幅度以实际桌宠尺寸判断 |
| `frogSway` | 左倾、短停、回中、右倾、回中；眼神与头身略有先后，脚底接触稳定 |
| `frogPeek / footSwing` | 好奇探头、交替摆脚；输入开始时从当前姿态收回 |
| 打字与鼠标 | 双手交替点按、指尖压下再回弹；仅配置的原尾巴按键改为伸脚敲键 |
| `nap` | 手先靠拢、身体缓缓伏下、闭眼呼吸；自然起身或被输入惊醒，均从当前进度过渡 |
| 起床气与安抚 | 惊醒抬头、眼皮压低、嘴边鼓腮、脚掌蓄力跺地，落点配尘圈与可读文字；抚摸或随机 2–5 秒恢复 |
| 连续输入 | 专注、左右律动、兴奋、生气；复用现有触发状态，避免停止输入后持续强烈敲击 |
| 五种道具 | 拿取、入口、放回共同阶段；咖啡专注、奶茶开心、可乐惊讶、能量饮料兴奋、布丁满足 |
| 其他小动作 | 鼓腮吐气、小跳、拍肚皮、揉脸、伸懒腰、招手、抱肚；以后再考虑翻身或打滚 |

奶蛙保持**无专属音效**，键盘和鼠标声音继续使用独立设置。不要随模型自动添加蛙叫或跺脚声。

优先级建议：隐私/重置 > 当前持物和接触约束 > 用户输入与惊醒 > 表情反应 > 手动或自动待机。对姿态和表情分层混合，避免全身动作抢走持杯手。停止、换模型或改变键鼠布局后释放旧接触点与动画状态。

## 当前项目还需要补什么

本方案基于当前源码和已安装 Three.js 源码核对：

- [catEngine3d.ts](../src/catEngine3d.ts) 当前通过程序创建猫咪网格与部件，运动逻辑依赖猫咪头部、尾巴和爪子。不是外部角色通用播放器。
- [naiwaPose.ts](../src/naiwaPose.ts) 已定义 `lift/squash/lean/tilt/sleep/gaze/lids/cheeks/mouthOpen/bellyPat/hands/feet`，适合复用行为语义；其中二维坐标必须映射为新 3D 骨架坐标，不能直接套用。
- 已安装 Three.js 包含 `GLTFLoader`、`SkinnedMesh` 与 `AnimationMixer`，可用于加载蒙皮网格和播放动画；项目目前没有把这些能力接成外部奶蛙模型导入流程。
- [models.rs](../src-tauri/src/models.rs) 的模型包仍是大小上限 256 KB 的 JSON 配色配置，不能容纳完整 GLB、贴图和动作。

建议实现顺序：

1. **外观样机**：在 Blender 保存可编辑源文件，导出坐姿与趴姿静帧，按参考图和桌宠大小验收；通过后再绑定动作。
2. **独立运行时适配器**：新增 `three-naiwa-v1`，实现加载、销毁、挂点查询、姿态混合和输入响应。复用现有桌面、道具、输入事件和情绪调度，模型内部骨架独立。功能完成前不把它标为可用适配器。
3. **接触与表情验证**：先打通双手键鼠、喝饮料和趴睡，再扩充待机动作。保留共同 `cat-v1` 行为语义，按需扩展版本化能力声明，不通过模型名字猜骨架。
4. **模型包下一版**：设计含清单、GLB、预览图和许可证信息的包，分开校验清单与资源大小。导入检查路径、挂点、动画名称、形态键和材质槽；更新存储、导出、删除与 GitHub 模型目录，旧配色包继续兼容。
5. **UI、MCP 与预览**：完整能力写入共享契约后再开放 3D 分类、模型图片、动作按钮与 HTML 验证页面。加载失败保留当前模型并提示具体原因。

必须有的挂点沿用 [modelContract.json](../src/modelContract.json) 的规划：`mouth`、`gripLeft`、`gripRight`、`footContactLeft`、`footContactRight`。建议再增加头部抚摸范围和脚底支撑面元数据。嘴部挂点不能只放在未变形的网格上；张嘴、鼓腮或趴睡时需要跟随相应面部控制，确保饮用对位。

## 验收重点

- 参考图正面、侧面、趴姿与实际显示大小下都保持角色辨识度，不能只在大图正面好看。
- 肩、臂、掌无断裂；鼠标左右摆放、65/108 配列、不同键盘朝向和缩放下都能轻触，五种道具入口对位。
- 在趴下、探头、倾斜、持杯途中触发输入、停止、隐私或换模型，连续过渡，不跳回默认姿态。
- 眼皮覆盖完整；鼓腮只影响嘴边；躯干倾斜时脚底不滑，跺脚和落地特效出现在真实接触点。
- 在目标 Windows/macOS/Android 设备实测后才确认面数与贴图预算，构建与安装包测试继续交给 GitHub。

实施时首先交付一份参考图匹配的静态样机和一个“打字—点鼠标—趴下—惊醒”连贯演示，再进入模型库接入；这比一开始堆叠大量动作更容易验收造型与接触问题。
